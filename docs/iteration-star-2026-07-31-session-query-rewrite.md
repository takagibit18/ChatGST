# 会话轮次与 Query Rewrite 优化复盘（STAR）

日期：2026-07-31

## S — Situation（背景）

本地政策问答 MVP 原先将单个会话硬编码为最多两次输入，澄清地区后几乎无法继续追问；前端快捷操作也在第二次输入后禁用。Query Rewrite 又以“原问题超过 60 字”为触发条件，导致群众常用的短句、口语和信息不完整问题反而无法得到语义改写，而普通明确问题曾产生约 9.7 秒 Rewrite 和约 3 秒 rerank 延迟。

## T — Task（目标）

- 将会话输入上限提高为可配置的 20 次，并保留一键清空服务端和页面会话的能力。
- 系统模型、工具或输出校验异常不得消耗用户轮次。
- 移除 60 字长度规则，建立“确定性识别优先、模糊问题提前改写、零命中补偿改写”的混合查询链路。
- 保证 Rewrite、rerank 和最终回答仍受每请求两次模型调用预算约束。

## A — Action（行动）

- 新增 `MAX_SESSION_TURNS=20`，Runtime 使用配置值校验轮次；删除“两轮内仍缺地区”的特殊分支和前端两轮按钮限制。
- 复用现有 WebSocket `reset/session_reset` 协议，确认重置时删除旧状态、生成新会话 ID 并清空页面消息。
- 仅在有效业务回答、澄清、证据不足或主动安全拒绝时累计轮次；输出校验导致的系统安全降级不保存为有效轮次。
- 为归一化查询增加 `intentConfidence`，补充“能不能领、去哪领、一年给多少”等口语意图规则。
- 将 DeepSeek Rewrite 改为结构化 `{ query, intent }`，对空值、非法 JSON、非法意图和超长结果执行确定性回退。
- 地区缺失时直接澄清；低置信度意图在检索前 Rewrite；明确问题首轮零命中时 Rewrite 后只重试搜索，版本解析不重复执行。
- 每次请求最多使用一次 Rewrite 或 rerank，始终为最终回答预留一次模型调用。
- 增加会话上限、重置、失败不计轮次、口语识别、模糊查询、零命中重试及 Rewrite 校验测试，并更新 smoke 流程。

## R — Result（结果）

- TypeScript 编译和前端生产构建通过。
- 自动化测试由 39 项增加到 44 项，8 个测试文件全部通过；smoke 验证第三次输入和重置后继续提问均成功。
- 实际操作日志中同一会话连续完成至少 8 次输入，未再出现两轮限制。
- 明确问题的 Rewrite 被稳定跳过，检索阶段约 54～82ms；零命中 Rewrite 约 0.95～1.16 秒，明显低于旧链路约 9.7 秒的改写延迟。
- 本轮 5 次正常 DeepSeek 回答全部一次通过输出校验，rerank 均未额外调用；主要耗时已收敛到最终回答生成的约 2.27～4.33 秒。
- 后续日志同时暴露了四项待改进点：本体 `missing_info` 未控制最终回答、口语意图未同步生成规范检索词、跨轮意图继承过宽、弱命中未触发补偿。这些问题进入下一轮修复。
