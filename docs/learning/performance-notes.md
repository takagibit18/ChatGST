# Agent 对话性能采集清单

> 采集对象：pi-coding-agent（Earendil Works, v0.80.7, MIT 开源）
> LLM 后端：DeepSeek V4 Flash


---

## 一、测试矩阵设计

### 1.1 五个维度 × 各 5 条 = 25 条用例

| 维度       | 目标                | 用例数 | 示例                                                 |
| -------- | ----------------- | :-: | -------------------------------------------------- |
| **代码生成** | 测长文本输出延迟          |  5  | 写排序函数 / 实现 REST 接口 / 写单元测试 / 重构代码 / 写正则            |
| **文件操作** | 测工具调用准确率 + 往返延迟   |  5  | 读文件并总结 / 查找函数定义 / 批量修改变量名 / 写新文件 / grep 搜索         |
| **知识问答** | 测短回复延迟            |  5  | 解释概念 / 对比技术 / 最佳实践 / 版本差异 / 错误排查                   |
| **多轮对话** | 测上下文保持 + Token 膨胀 |  5  | 连续追问 4~6 轮 / 修正前一轮 / 补充需求 / 切换话题再回来                |
| **工具组合** | 测多工具协作            |  5  | 读→改→写 / grep→定位→edit / ls→分析→输出 / 读多文件→对比 / 创建项目结构 |

### 1.2 稳定性：每类选 1 条 × 跑 3 次

用于区分冷启动 vs 热缓存，取 P50/P95。

## 二、延迟指标

| 指标 | 测试方法 | 简历表述 |
|------|----------|----------|
| **首 Token 延迟 (TTFT)** | 发送 prompt → stream 收到第一个 content block 的时间 | "首 Token 响应时间" |
| **完整回复耗时** | 发送 prompt → 收到 `done` 信号的总时间 | "端到端对话延迟" |
| **流式间隔** | 相邻两个 streaming chunk 的时间差（P50/P95/P99） | "流式输出平滑度" |
| **工具调用往返** | Agent 发出 tool_call → 收到 tool_result 被送回 LLM 的时间 | "工具调用回合延迟" |
| **冷/热启动差异** | 同一 prompt 第 1 次 vs 第 3 次的延迟差 | "冷启动开销" |

---

## 三、Token 消耗

| 指标                     | 测试方法                                        | 简历表述                |
| ---------------------- | ------------------------------------------- | ------------------- |
| **Prompt Token/轮**     | 每轮 system prompt + user message 的输入 token 数 | "单轮输入 Token"        |
| **Completion Token/轮** | 每轮回复的输出 token 数                             | "单轮输出 Token"        |
| **工具注入开销**             | 加载 Skill 前后的 system prompt token 差          | "Skill 注入 Token 开销" |
| **工具定义开销**             | 注册 N 个工具后 system prompt token 增量            | "工具定义 Token 开销"     |
| **多轮累计消耗**             | 1/3/5/10 轮后的累计 Token                        | "多轮 Token 增长曲线"     |
| **上下文压缩收益**            | compaction 前后的 prompt token 差               | "压缩节省 Token 比例"     |

## 四、吞吐与容量

| 指标          | 测试方法                            | 简历表述        |
| ----------- | ------------------------------- | ----------- |
| **并发退化点**   | 1/3/5/10 并发，找延迟 ≥ 2× 基线的点       | "并发吞吐上限"    |
| **长对话衰减**   | 单会话 1→20 轮，每轮追加消息，测首 token 延迟变化 | "长对话性能衰减曲线" |
| **上下文压缩效果** | 触发 compaction 后，下一轮首 token 延迟变化 | "上下文压缩效率"   |

## 五、质量观察（定性 + 简单量化）

| 指标          | 测试方法                    | 简历表述           |
| ----------- | ----------------------- | -------------- |
| **工具路由准确率** | 25 条用例中，Agent 正确选择工具的比例 | "工具调用准确率 X/25" |
| **工具参数正确率** | 调用了正确工具且参数无误的比例         | "工具参数正确率"      |
| **多轮上下文保持** | 第 N 轮追问中正确引用第 1 轮信息的比例  | "多轮上下文保持率"     |
| **输出格式合规**  | 回复是否符合 JSON/代码块/列表等预期格式 | "输出格式合规率"      |
